# 百面相（Polyphony）

百面相从千千结读取人物资料，并承接镜头外的群像生活。手机界面按视、听、嗅、味与设置组织。视页采用右侧覆盖人物抽屉与可沿边拖动的局部玻璃入口，位置仅当前界面内存；听页为直接阅读的场外事务清单，味页为已有稳定社交群及其风向清单，窗口可选雾蓝杏色日间、蓝绿夜间或跟随酒馆。双面具悬浮球可以拖动，点击开关面板，顶栏控制显隐。

## 安装内测版

1. 安装并启用支持剧情楼层就绪通知的千千结。[千千结](https://github.com/atonal519/ST-MyriadKnots)
   - 原版 SillyTavern 和 Luker 使用白鳥数据后端 0.2.0。原版白鳥装在服务端 `plugins/ST-BaiNiaoData`，在 `config.yaml` 设定 `enableServerPlugins: true` 后重启酒馆服务。安装流程已在原版 SillyTavern 1.19.0 验证。[白鳥安装说明](https://github.com/atonal519/ST-BaiNiaoData#安装)
   - TauriTavern 2.2.0 及以上使用 TT 本地存储。请安装支持 TT 的千千结。
2. 在酒馆的扩展页选择「安装扩展」，填入 `https://github.com/atonal519/ST-Polyphony`。
3. 打开一个聊天，等千千结的资料就绪。从魔棒菜单打开百面相，在「设置 → 通用设置 → API 配置」选择主、副模型，再点「世界观 → 百相流转」。首次会先整理人物与世界基础。

本次版本为 `0.1.2`。[内测公告](docs/updates-0.1.2.md)

## 当前界面与人物发展

视页可选择全部人物，显示简短身份及局部图，图中分开表达明确人际关系、参与事务和情绪圈层。听页展示场外事务（含已完成），只排除参与者非空且全部明确在场的卡片；混合事务保留完整参与者，空或未知参与者不猜测排除。人物图中的事务入口与听页可见清单一致。听先显示本轮已更新的事项，两组各按推进中、等待中、计划中、已完成排列。整条事项收束后才显示已完成。听页显示完整的最新有效进展或事务概况，保留段落。仅有已存前情时显示三角，点击正文可沿同一细线由新到旧展开。正文下左侧是状态，右侧是人物。1 至 3 人直接点头像跳转，4 人起以三个叠头像打开完整名单。嗅按已有载体显示左弧叠放的毛玻璃夹。滑动、滚轮和方向键可换焦，点可见夹页在百面相窗口内展开。首批最多八条连续排列，更多历史按需追加。正文保存在白鳥，打开夹页才按批读取。味页持续展示有效群名、当前在群成员及32px高全宽Plasma横幅；没有风向时显示已知群说明，有明确归属的风向时直接显示各圈已接纳的模型说明，数值风向与旧无数值风向一致，直接关系仅在已有归属风向时补卡，标题按长期共同往来命名，同一关系多条风向共用一个主体名；标题静态展示，短简介直接完整显示，只有真实超过两行的长文才显示三角并可点击展开、收起同一完整原文。经历的生成、保存与后续承接保持，QQJ原资料与回忆仍按原合同读取。

设置的“世界构建”可随时重整人物与社交基础，不依赖新增剧情：一次主模型重读完整许可卡书、必要QQJ字段与稳定正文，重新核对自动人物、群、明确关系及影响生活的环境规则。构筑同答整理基础，风向与自主生活沿味、听生成。同一圈保原ID，有据不适用的自动圈可结束后重新分组，保留已有经历、知情和人工内容，不补演空档。构建保留当前聊天原有自动流转资格；未启用档仍需点击“百相流转”，已启用档构建或重存后等待后续稳定剧情，不立即追加味、听请求。较早已处理正文只作参考，不回退当前时钟、事务或处理位置。已有确认聊天身份与卡书资料的新卡暂无稳定正文时，也可先构筑静态基础；最新AI仍排除。“百相流转”先由味用一次副模型形成局部风向并保存，再由听用一次主模型读取实际保存结果，发展事务、经历和知情；听的结果成功保存后开启此聊天自动发展。构建后手动首次流转处理同一基线当前时点；已启用档收到新的稳定楼时沿原处理位置累计，达到N后只做原一轮味、听。新用户消息或新一轮生成开始后，等待千千结正式保存所需摘要与人物状态；就绪后立即处理上一楼，即使新AI仍在生成。手动流转也可读取已就绪的末个AI楼。可直接点流转；缺基础时会自动补这唯一一次构筑，已有基础后仍为两次。

世界观标题下、两个操作按钮上方显示一行状态：正常待启用、等待和工作中为绿色，需要处理的失败或暂停为橙色。状态复用当前配置、已保存世界及真实进度；失败、停止和待重存会说明可继续操作的原因，不增加开关、健康检查请求或后台轮询。

内容设置“几楼一更新”默认1；按正式新AI正文累计，输入包含其间user正文，达到N以同批关联资料完成味与听两模块；首次缺基础时先独立构筑并保存，共3次，已有底账后2次。百相流转可在未满N时提前处理。安装、开面板、旧启用设置或旧启动标记不会发模型；新聊天正文/QQJ身份未起步正常等待。

普通流转用一次千千结批读为味和听取材。味取相关圈的公开气氛，听为少量合适的人物抽取短创作角度，让他们在场外发展自己的生活。旧事项遇到实质变化时沿原 ID 承接，新目的可以形成自己的事项。旧经历和各人的知情完整保存在世界里。完整卡书由首次或显式世界构建读取。

请求期间新楼留到成功保存后按最新 N 检查。正常流转中的可读回包按条校验。即使没有可保存的新事务，已启用的聊天也会结算本轮进度，继续等待下一批稳定正文。请求失败、无法读取结果或保存失败时暂停并提示。保存失败可重存同候选，不重发该模块，风向重存成功后继续尚未派发的人物发展。风向已保存而人物发展失败或停止时，下次明确操作只续剩余模块；真实冲突不盲写。每次派发前读取对应模型的最新已保存配置。副模型跟随主模型时，味使用当时的主配置。人物事件只记录已发生结果，未来意图保留为持续事务；主聊天回流尚未接通。

视、听、嗅、味共用一套健康条、页边距和首项间距，并随界面缩放。设置以「启用百面相」开头，字号 18px、字重 600。总开关、版本更新、世界书排除及提示词/包裹符沿用千千结交互。API用途行与编辑弹窗沿用千千结布局，并随百面相外观切换。外观可调整主题、75–150% 缩放和字体 CSS URL，默认 85% 与 387 字体。通用设置除外观外共用白鳥设置，世界书排除先于读取生效，正文按共享包裹符清洗。破限提示词使用`schedule-planner.processingPrompt`，每次实际文字请求读取；留空使用内置默认；恢复默认清空草稿，保存后生效，载入内置默认仅把全文填入草稿。原草稿、取消与保存交互保持。桌面窗口可拖动顶栏空白、拖动右下角调整大小，位置与尺寸作为百面相独立本地UI偏好保存；桌面默认360×600、顶部70，尺寸受可视视口限制；手机左右各留10，上下按千千结现行安全区留空。手机外侧完整点按关闭，滑动与其它弹窗不串关；宿主输入框继续正常获焦，内部编辑期间保留键盘原行为。固定蓝壳暂不随原主题模式换配方；原主题get/save继续有效。窗口沿既有Shadow DOM隔离，内部依据与历史工作台不显示。

构筑支持无外置主绑定时的卡内嵌书，外置主绑定优先；整本排除先于读取，某书失败继续其余材料。人物短基础与环境保存在同一世界，后续味、听直接沿用。取材人物的自动性格缺口会继续交给正常味/听请求，复用当批资料及已存有效生活经历有据补充；已有主干保留，新细节凝练整合，当前情绪不直接变成长久性格。空性格不触发每轮重读全书，未知可暂空；人工决定及明确留空优先，空或坏返回不擦旧值。有据底账性格可在QQJ性格为空时供听和下一次正常头像提炼使用，不回写QQJ。局部字段、成员、关系或可选出处出错时，保留能确定的内容；人工修改及明确清空优先。旧档缺少环境不会自动重构，需手动世界构建时才重整。

## 数据与边界

正常加载、完成回调、未派发原因、模型原答/错误、解码/应用与保存回应会在插件专用白鳥记录 `st-dollars / diagnostics-development / recent` 有界留证，可由后台直接读取。两模块分别保留原答并关联同批操作。保留最近12次触发或操作（含挂载、跳过及保存后检查），24小时窗口在新事件时裁剪；单份原答最多256KiB、原答合计512KiB、整份记录最多640KiB，截断明确标注。凭证、完整设置、输入正文和人物档案不写诊断；诊断失败不影响业务结果、不自动重试，没有常驻采集或额外模型调用。诊断记录不代替权威世界，也不能还原安装前已丢失的日志。

人物目录合并千千结公共桥与本world的最小人物底账，包含世界书明确但尚未出场的人物；不复制QQJ整份档案/NSFW栏目。百面相世界仍保存在白鸟 `st-dollars / npc-world-{QQJChatId} / world`。姓名、事件、时间和正文均使用原记录；无内容不补写人设或当前动作。世界处理楼号、旧活动状态或数组追加位置不能当人物实时状态。

API 设置外部保留主副模型选择与编辑，下方一个“新增 API”。连接名称、URL、Key、模型、拉取、测试、另存和删除在弹窗内；保存成功才生效，取消保留原配置，Key 留空保留最新值。副模型跟随主模型时编辑实际使用的主配置。新增与另存只创建共享连接，不切换用途，首次创建后也需自行选择。弹窗独立定位，正文滚动、底部操作保留；关闭面板或离开设置会取消未保存草稿和待打开动作。

模型设置仍独立于主聊天；原配置消费者和保存功能保持。仅阅读已有记录不发模型或写世界；设置中显式测试等既有动作仍按用户操作执行。新增分类尚未做真实模型质量与安卓实机验收。

## 源码与构建

发行包已包含 `dist/`，酒馆按 `manifest.json` 加载。开发时安装依赖后可从源码重新构建。

```sh
npm test
npm run typecheck
npm run build
```

实现说明见[架构](docs/architecture.md)，产品当前范围见[设计](docs/design.md)。

Smile 头像首次显示时按当时的性格线索选定双色与表情范围，未命中时沿人物 ID 稳定选配。同一聊天后续沿用已选类型，并随正常世界保存带上。主面板仍用原 Interference 底纹，撞色圆斑横向错开。味用 Plasma 纹理作圈名背景，沿用原开源配色，并按当下主要情绪加强三个色位。界面展示颜色和自然说明，成分与数字供内部更新及听承接。旧档保留冷、中、暖及节奏分类展示。风向展示与明确关系提取沿用原请求。QQJ 对应原字段变化时，关系提示按新来源核对。

味风向用可选circleRef精确关联有效群/关系；兼容旧唯一G/R依据，未知或多主体不猜。味卡与听/检索背景共用当前群名或双方姓名，关系角色仍保留在取材语义中；旧档读取即生效，无需重跑生成。旧无归属记录保原存储供正常味修正，不当正式圈送听或检索。听显示层补缺失句末标点，不改存档原文；同一事项模型应沿旧ID，不以角色视角重建。听觉以场外人物的日常为首要取材，正文校准保留在场者已知事实作为约束，不用复述在场活动代替场外生活；所有原活动、事件与知情仍完整保存。

味按公开表现判断当前气氛，人物长期资料只作人设约束。卡片直接保留已接纳description，同圈各段仅对完全相同文字去重；publicBasis仅作内部依据，不按分数或持续原因标记另拼开头、气氛句或收尾。没有新模型说明时保留原文。无新公开交流、可信时间推进或事实校准时保留旧强弱；日常小摩擦只能小幅回升，不能逐轮堆到极端。可信故事时间让短时起伏逐渐平复，未定事项可保留适量牵挂；长期关系仍由既有基础承接。准备阶段的部分附加资料失败、缺少可派生标题或个别坏群成员均局部处理，能确认的内容继续使用。
